文档范围与安全提示

Scope and safety

本文档依据仓库当前 0.1.0-dev、稳定 C ABI API v1、公开头文件和 CLI 实际帮助输出编写。

This guide reflects the repository's current 0.1.0-dev build, stable C ABI API v1, public headers, and actual CLI help output.

刷机是破坏性操作。在执行 flash、erase、format、update、锁定或解锁前，请确认设备、分区、产品和镜像哈希。断电或传输状态不确定时，KairosBoot 不会猜测偏移量并自动续传。

Flashing is destructive. Before flash, erase, format, update, lock, or unlock, verify the device, partition, product, and image hash. KairosBoot does not guess an offset or auto-resume after power loss or an uncertain transfer.

项目仍处于 1.0 前开发阶段。当前软件里程碑以 GitHub-hosted Release CI、脚本化协议/传输测试、安装包 smoke test 和锁定版本的官方 Fastboot 差分测试为验收边界。真实 USB 硬件验收已明确延期；当前不需要 self-hosted runner，HIL 工作流保留但默认不启用。本文档不声称已验证真实吞吐、32 台设备并发、硬件故障注入、24 小时 soak 或生产刷机安全。

The project is still pre-1.0. The current software milestone is bounded by GitHub-hosted Release CI, scripted protocol and transport tests, package smoke tests, and differentials against the locked official Fastboot. Real USB hardware qualification is explicitly deferred: no self-hosted runner is required now, and the retained HIL workflow stays disabled by default. This guide makes no claim of validated real-device throughput, 32-device concurrency, hardware fault injection, 24-hour soak behavior, or production flash safety.

公开接口

Public surfaces

C11 单头文件、C++23 RAII 包装、C# 异步 API 与 kairosboot CLI。C++ 和 C# 最终调用相同的稳定 C ABI。

A single-header C11 SDK, C++23 RAII wrapper, asynchronous C# API, and the kairosboot CLI. C++ and C# ultimately use the same stable C ABI.

设备端要求

Device requirement

KairosBoot 是纯 Host 侧实现，连接支持标准 Fastboot 协议的 bootloader 或 fastbootd，不要求修改设备端。

KairosBoot is host-only. It connects to a bootloader or fastbootd that implements the standard Fastboot protocol and requires no device-side changes.

Build and quick start

从源码构建

Build from source

性能测试与发布产物必须使用 Release 配置。多配置生成器仍应在 build/install 阶段显式传入 --config Release。

Performance measurements and release artifacts must use the Release configuration. With a multi-config generator, pass --config Release explicitly to build and install.

cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON
cmake --build build --config Release
ctest --test-dir build --build-config Release --output-on-failure
cmake --install build --config Release --prefix <install-prefix>

KairosBoot 动态链接 libusb。Windows 设备需已安装兼容的 WinUSB 驱动；库只提供诊断信息，不会替换驱动。网络传输由 Boost.Asio 实现，对使用者不暴露 Winsock API。

KairosBoot dynamically links libusb. Windows devices need a compatible WinUSB driver; the library reports diagnostics but never replaces the driver. Network transports use Boost.Asio and do not expose Winsock APIs to consumers.

设备选择与传输

Device selectors and transports

CLI 与 Fastboot 一致，使用 -s SERIAL 或 -s tcp|udp:HOST[:PORT]。API 只在打开 Device 对象时接收 selector：C 使用 kb_device_open，C++ 使用 Context::open_device，C# 使用 Context.OpenDevice；之后所有单设备操作都直接调用该对象，不再重复传 selector。无参打开只在当前恰好有一台 USB Fastboot 设备时自动选择，否则返回 no-device 或 ambiguous-device。

Like Fastboot, the CLI uses -s SERIAL or -s tcp|udp:HOST[:PORT]. APIs accept a selector only while opening a Device: kb_device_open in C, Context::open_device in C++, and Context.OpenDevice in C#. Every subsequent single-device operation is invoked on that object without repeating a selector. The parameterless form auto-selects only when exactly one USB Fastboot device is present; otherwise it returns no-device or ambiguous-device.

CLI 使用

CLI usage

常用刷写流程

Common flashing workflow

# Read-only identity checks
kairosboot -s ABC123 getvar product
kairosboot -s ABC123 getvar current-slot

# Flash one image; choose an explicit device in multi-device environments
kairosboot -s ABC123 flash boot images/boot.img

# Flash a package; preserves userdata by default
kairosboot -s ABC123 update image-product.zip

# Apply package wipe tasks and skip final reboot
kairosboot -s ABC123 -w --skip-reboot update image-product.zip

# Use a slot and activate it before prepared flash tasks
kairosboot -s ABC123 --slot b --set-active=b flash boot images/boot.img

# Reboot explicitly
kairosboot -s ABC123 reboot

同一条命令可重复传入 -s 并行操作最多 32 台设备，例如 kairosboot -s SERIAL_A -s SERIAL_B flash boot boot.img。fetch 与 get_staged 会写入单个主机文件，因此拒绝多个 -s，避免不同设备覆盖同一路径；请为每台设备分别指定输出文件。

Repeat -s on one invocation to run the same command concurrently on up to 32 devices, for example kairosboot -s SERIAL_A -s SERIAL_B flash boot boot.img. fetch and get_staged write one host file, so they reject multiple -s values to prevent devices from overwriting the same path; invoke them separately with distinct output files.

镜像、动态分区与接收

Images, dynamic partitions, and receive

# Build and boot an Android boot image from components
kairosboot -s ABC123 --header-version 2 --dtb board.dtb \
  boot kernel.bin ramdisk.img

# Replace a named vendor_boot v4 ramdisk and optional DTB
kairosboot -s ABC123 --dtb board.dtb \
  flash vendor_boot:default vendor-ramdisk.img

# Create or resize a logical partition
kairosboot -s ABC123 create-logical-partition scratch 1073741824
kairosboot -s ABC123 resize-logical-partition scratch 2147483648

# Enter userspace Fastboot with the canonical Platform-Tools spelling
kairosboot -s ABC123 reboot fastboot

# Fetch a partition atomically to a file
kairosboot -s ABC123 fetch vendor_boot vendor_boot.img

# Stage and retrieve data
kairosboot -s ABC123 stage metadata.bin
kairosboot -s ABC123 get_staged staged-output.bin

resize-logical-partition 会先判断设备模式。在 fastbootd 中，它经过槽位与 logical 检查后发送标准 resize 命令；在 bootloader 中，它会读取有界的 super 元数据、在 Host 侧校验并调整 liblp 表，然后下载 metadata-only sparse super 并刷写 super。任一校验失败都会在破坏性下载前终止。

resize-logical-partition first checks the device mode. In fastbootd it sends the standard resize command after slot and logical checks. In the bootloader it fetches a bounded super metadata prefix, validates and updates the liblp tables on the host, then downloads a metadata-only sparse super image and flashes super. Any validation failure stops before the destructive download.

C11 API

C11 API

包含单一公共头文件 kairosboot/kairosboot.h。接口使用 UTF-8、固定宽度整数与 opaque handle；库创建的 handle、error、result 和 report 必须由对应的 kb_*_release() 释放。

Include the single public header kairosboot/kairosboot.h. The API uses UTF-8, fixed-width integers, and opaque handles. Handles, errors, results, and reports created by the library must be freed with their matching kb_*_release().

最小阻塞式刷写

Minimal blocking flash

#include <kairosboot/kairosboot.h>
#include <stdio.h>

int main(void) {
  kb_context_t *context = NULL;
  kb_device_t *device = NULL;
  kb_error_t *error = NULL;
  kb_status_t status = kb_context_create(NULL, &context, &error);
  if (status == KB_OK) {
    /* NULL auto-selects only when exactly one USB device is present. */
    status = kb_device_open(context, NULL, &device, &error);
  }
  if (status == KB_OK) {
    status = kb_flash_file(device, "boot", "boot.img", NULL, &error);
  }

  if (status != KB_OK) {
    fprintf(stderr, "KairosBoot: %s\n",
            error != NULL ? kb_error_message(error) : kb_status_string(status));
  }
  kb_error_release(error);
  kb_device_release(device);
  kb_context_release(context);
  return status == KB_OK ? 0 : 1;
}

异步、进度与取消

Async, progress, and cancellation

static kb_progress_action_t KB_CALL on_progress(
    const kb_progress_t *p, void *user_data) {
  int *cancel_requested = (int *)user_data;
  fprintf(stderr, "%s: %llu/%llu\n", p->stage,
          (unsigned long long)p->bytes_completed,
          (unsigned long long)p->bytes_total);
  return *cancel_requested ? KB_PROGRESS_CANCEL : KB_PROGRESS_CONTINUE;
}

int cancel_requested = 0;
kb_flash_options_t options;
kb_flash_options_init(&options);
options.timeout_ms = 30000;
options.progress_callback = on_progress;
options.progress_user_data = &cancel_requested;

kb_device_t *device = NULL;
kb_operation_t *operation = NULL;
kb_status_t status = kb_device_open(context, "ABC123", &device, &error);
if (status == KB_OK) {
  status = kb_flash_file_async(
      device, "boot", "boot.img", &options, &operation, &error);
}
if (status == KB_OK) {
  /* Another thread may call kb_operation_cancel(operation). */
  status = kb_operation_wait(operation, KB_WAIT_INFINITE);
  if (status != KB_OK) {
    const kb_error_t *borrowed = kb_operation_error(operation);
    fprintf(stderr, "%s\n", borrowed != NULL
        ? kb_error_message(borrowed) : kb_status_string(status));
  }
}
kb_operation_release(operation);
kb_device_release(device);
kb_error_release(error);

每个 operation 的回调串行执行，且不在 libusb event thread 上运行。progress_user_data 必须保持有效直到 operation 释放；不要在自己的回调里释放同一个 operation。kb_operation_error() 返回借用指针，不要单独释放。

Callbacks are serialized per operation and never run on the libusb event thread. progress_user_data must remain valid until the operation is released; do not release that operation from its own callback. kb_operation_error() returns a borrowed pointer and must not be released separately.

options 与 ABI 前向兼容

Options and ABI forward compatibility

始终调用对应初始化函数，再修改所需字段。NULL options 采用安全默认值；当前头文件的初始化宏会把调用路由到 sized initializer，并正确设置 struct_size 与 api_version。

Always call the matching initializer before changing fields. NULL options use safe defaults. The current header routes initializer calls to sized initializers, setting struct_size and api_version correctly.

kb_update_options_t options;
kb_update_options_init(&options);
options.wipe = 0;
options.skip_reboot = 1;
options.slot = "b";
options.set_active = 1;
options.active_slot = "b";

    context, "tcp:192.0.2.10:5554", &device, &error);

C++23 API

C++23 API

kairosboot/kairosboot.hpp 是 stable C ABI 之上的 header-only、move-only RAII 包装，使用 std::expected、std::filesystem、std::chrono 与 std::stop_token。

kairosboot/kairosboot.hpp is a header-only, move-only RAII wrapper over the stable C ABI, using std::expected, std::filesystem, std::chrono, and std::stop_token.

阻塞式刷写

Blocking flash

#include <kairosboot/kairosboot.hpp>
#include <filesystem>
#include <iostream>

int main() {
  auto context = kairosboot::Context::create();
  if (!context) {
    std::cerr << context.error().message() << '\n';
    return 1;
  }

  auto device = context->open_device("ABC123");
  if (!device) {
    std::cerr << device.error().message() << '\n';
    return 1;
  }

  kairosboot::FlashOptions options;
  options.timeout = std::chrono::seconds{30};
  options.progress = [](const kairosboot::Progress &p) {
    std::cerr << p.stage << ": " << p.bytes_completed
              << '/' << p.bytes_total << '\n';
    return kairosboot::ProgressAction::Continue;
  };

  auto flashed = device->flash_file(
      "boot", std::filesystem::path{"boot.img"}, options);
  if (!flashed) {
    std::cerr << flashed.error().message() << '\n';
    return 1;
  }
}

    using var device = context.OpenDevice("usb:1-2.3");

        packagePath: "image-product.zip",

Device 批量操作

Device batch operations

using var first = context.OpenDevice("ABC123");
using var second = context.OpenDevice("ABC124");
DeviceBatchReport report = await DeviceBatch.FlashFileAsync(
    new[] { first, second },
    partition: "boot",
    filePath: "boot.img",
    options: FlashOptions.Default,
    maxParallelDevices: 2,
    continueOnError: true,
    cancellationToken: cancellation.Token);

foreach (DeviceBatchResult result in report.Devices)
    Console.WriteLine($"{result.Identifier}: {result.Status}");

异步取消会先请求 native cancellation，然后继续 drain operation 与回调，再释放 SafeHandle；因此取消令牌触发不代表设备 I/O 已在同一瞬间停止。

Asynchronous cancellation first requests native cancellation, then drains operations and callbacks before releasing SafeHandles. A token firing therefore does not mean device I/O stopped at that exact instant.

多设备批量操作

Multi-device batch operations

调用方先打开互相隔离的 Device 对象，再把这些对象显式传给批量 API。设备顺序决定稳定的 report index；库不会重新枚举、重新匹配 selector 或读取外部任务文件。

Open isolated Device objects first, then pass them explicitly to the batch API. Device order defines stable report indexes; the library does not re-enumerate, rematch selectors, or read an external job file.

/* C11: explicit Device ownership and one-to-many flash. */
kb_device_t *devices[] = { first, second };
kb_device_batch_options_t batch_options;
kb_device_batch_options_init(&batch_options);
batch_options.max_parallel_devices = 2;
batch_options.continue_on_error = 1;

kb_device_batch_report_t *report = NULL;
kb_status_t status = kb_flash_file_batch(
    devices, 2, "system", "system.img", NULL,
    &batch_options, &report, &error);
  • 同一个 Device 不能重复出现在同一批次；每个对象保留独立会话和错误状态。
  • A Device cannot appear twice in one batch; every object keeps an isolated session and error state.
  • continue_on_error 隔离单设备失败；取消会传播给所有活动 operation。
  • continue_on_error isolates one-device failures; cancellation propagates to every active operation.
  • 同一设备内的 Fastboot 命令严格串行；并发发生在设备之间与 DATA transfer pipeline 内。
  • Fastboot commands remain strictly serial per device; concurrency occurs across devices and inside the DATA transfer pipeline.

CLI 使用与 Fastboot 对齐的命令名；重复 -s 即可并行执行同一设备命令，例如 kairosboot -s ABC123 -s ABC124 flash system system.img。

The CLI keeps Fastboot-compatible command names. Repeat -s to run one command in parallel, for example kairosboot -s ABC123 -s ABC124 flash system system.img.

进度、取消与错误

Progress, cancellation, and errors

超时

Timeouts

flash/command options 是每次 I/O deadline；update/batch options 是整个操作 deadline。初始化后的默认值为无限，不代表系统不会因断连或协议错误失败。

Flash/command options use per-I/O deadlines; update/batch options use whole-operation deadlines. The initialized default is infinite, but disconnects and protocol errors still fail.

取消

Cancellation

取消是请求，不是线程强杀。释放 operation/batch 前等待 transport 与回调 drain，避免 use-after-free 和跨设备串线。

Cancellation is a request, not a thread kill. Transport and callbacks drain before operation/batch release to avoid use-after-free and cross-device mix-ups.

传输确定性

Transfer certainty

NotSent、PartialOrUnknown、FullyTransferred 描述失败时 Host 能确认的数据状态；状态不确定时必须重新建立可信会话。

NotSent, PartialOrUnknown, and FullyTransferred describe what the host knows after a failure. An uncertain state requires a newly trusted session.

接收文件

Received files

upload/get-staged/fetch 的 SDK file API 先写临时文件，只有收到精确 DATA 和终态 OKAY 后才原子替换目标；Fastboot CLI 只公开官方 get_staged 与 fetch 命令。

The upload/get-staged/fetch SDK file APIs write a temporary file and atomically replace the destination only after exact DATA and terminal OKAY; the Fastboot CLI exposes only the official get_staged and fetch commands.
